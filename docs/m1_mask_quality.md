# M1 — проверка CT-derived внешней маски пациента

Статус: **исследовательский путь; клиническое применение запрещено до
независимой проверки внешнего контура, стола и системы фиксации**.

## Причина отдельной проверки

В RTSTRUCT Validation Case 001 отсутствует `External/BODY/patient`.
Нельзя заменить его PTV, всем CT FOV или алгоритмической маской без
отдельной оценки возможного включения стола.

Внутри проекта исследовательская маска получается из HU threshold,
3D closing, компоненты, найденной от общего изоцентра, и посрезового
заполнения полостей. Если изоцентр находится в лёгком, поиск ближайшей
компоненты ограничивается заданным физическим радиусом и не создаёт
глобальный массив distance-transform для 187×512×512 CT.

## Как выполнить воспроизводимую диагностику

В локальной среде с оригинальным DICOM-экспортом:

```bash
pip install -e ".[dev,qc]"

indep-mu inspect /secure/case001

indep-mu patient-diagnostics /secure/case001 \
  --threshold-hu -600 --threshold-hu -500 --threshold-hu -400 \
  --closing-iterations 1 \
  --output /secure/results/case001_mask_review.json

indep-mu patient-qc-png /secure/case001 \
  /secure/results/case001_mask_review.png \
  --threshold-hu -500 --closing-iterations 1
```

Результаты остаются локальными. **Ни DICOM, ни изображения CT, ни JSON
с геометрией конкретного пациента не загружаются в GitHub.**

## Содержание результатов

Для каждого порога выводятся:

- объём маски в см³ и количество вокселей;
- число HU ниже и выше диапазона DRT120kV (−1000…+2009);
- ближайшая ткань к изоцентру и расстояние seed snap;
- Dice относительно −500 HU (если этот порог выбран);
- число добавленных/удалённых вокселей;
- относительная разность объёмов;
- касание границы CT;
- воксели вне маски, находящиеся позади неё, в пределах 50 мм
  по направлению DICOM +Y (для строго axial HFS).

### Ограничение posterior survey

Для axial HFS увеличение индекса CT row соответствует posterior patient
direction. Survey ищет плотные воксели за наиболее posterior границей маски
каждого axial slice в пределах её x-span.

**Если survey положительный:** имеются posterior candidates; нужны проверка
сканов и при необходимости отдельное описание стола.

**Если survey равен нулю:** это НЕ означает, что стол исключён.
Стол/подложка может быть физически соединён с телом и уже включён
в итоговый компонент сегментации.

Для non-axial / non-HFS геометрии такой способ не применяется: программа
должна завершить эту часть с явной ошибкой вместо неправильного определения
posterior направления.

В обоих случаях результат имеет статус:

```text
MANUAL_REVIEW_REQUIRED
```

## Принципиальная находка Case 001: опора ВНУТРИ mask

Повторная обработка исходного 187-slice CT и локальный визуальный QA
20.11.2026 выявили включение частей стола/подложки в исследовательский
3-D connected component при -500 HU.

Поэтому добавлен второй, комплементарный контроль:

- **posterior_survey** — возможные плотные объекты позади *готовой маски*,
  которые ещё не вошли в mask;
- **posterior_island_survey** — дополнительные posterior 2-D компоненты
  *внутри* выбранной 3-D маски, выявляемые посрезовой маркировкой.

Ни положительная, ни отрицательная проверка не является заменой
внешнего клинического контура. При числе подтверждённых posterior islands
более нуля на montage приоритетно включаются соответствующие срезы.

В случае 001 нужна новая, независимо просмотренная External/BODY структура
и отдельный Couch/Support слой. Результат `patient-diagnostics` может
использоваться только как research QA report.

## Визуальная проверка

Команда `patient-qc-png` создаёт локальную PNG-монтажную сетку с девятью
равномерно выбранными axial slices и контуром исследовательской маски.

Врач/физик должен независимо проверить как минимум:

1. не захватывает ли external-mask стол, breast board или другое support;
2. не обрезана ли кожа и грудная стенка;
3. сохранены ли области низкой плотности внутри грудной клетки;
4. не включены ли посторонние компоненты после fill_holes;
5. нет ли систематического смещения на разных z-уровнях.

PNG из CT остаётся медицинским изображением, даже если убрать DICOM
идентификаторы: хранить только в защищённом локальном контуре.

## Явное создание только исследовательского фантома

Поскольку внешняя маска ещё не прошла визуальную проверку, команда
`build-patient` по умолчанию **отвергает** CT-derived external-mask.
Чтобы выполнить исключительно исследовательский прогон, необходимо явно
подтвердить риск:

```bash
indep-mu build-patient /secure/case001 /secure/research-phantom \
  --derive-external-from-isocenter \
  --acknowledge-unvalidated-external-mask \
  --mixture-bins 9 \
  --out-of-range clip
```

Значение `mixture-bins 9` здесь является **только примером CLI синтаксиса**,
а не выбранным по результатам sensitivity study значением. То же относится
к `--out-of-range clip`: это явная исследовательская политика, пока не
оценены реальные outside-calibration HU и доза.

Наличие `--acknowledge-unvalidated-external-mask` означает только
осознанное создание исследовательских файлов. Оно не меняет
`validation_status = RESEARCH_ONLY` и не разрешает клиническое применение.

## Gate перед созданием validation .egsphant

`M1_REAL_PATIENT_VALIDATED` выставлять нельзя до:

- независимого визуального просмотра mask;
- решения об учёте PPS/couch как отдельного слоя;
- принятой политики HU вне калибровочного диапазона;
- сравнения mixture_bins sensitivity для PEGSless;
- проверки размеров, материалов и хеша конечного .egsphant;
- независимой проверки на дополнительных планах с trusted external contour.

CI с synthetic tests подтверждает работоспособность алгоритмов, но
**не заменяет эти проверки на реальном пациенте**.
